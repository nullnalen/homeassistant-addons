1. Deepen the database write module

Strong ports & adapters

bobil_v2.py · lines 375–684

Problem. update_database() er 310 linjer med 7 ansvar bak én interface. Ingen locality.

Solution. Trekk ut ChangeDetector og BobilRepository med smale interfaces. Scraperen kaller hver gjennom én seam.

Before — shallow (7 bands)

hent eksisterende DB-rad
normaliser & formater
detect felt-for-felt endringer
logg diffs til konsoll
bygg dynamisk SVV SQL
INSERT / UPDATE bobil
logg prisendringer + notify HA

Alle syv bak én funksjon. Endre én, bryt de andre.

After — deep (3 moduler)

ChangeDetector
detect(old, new) → ChangeSet
BobilRepository
upsert(ad, changes) → None
PriceLog
record(finnkode, old, new) → None

ChangeDetector testbar med plain dicts. Ingen MariaDB.

  • → locality: prisendring-logikk konsentreres i én modul, ikke spredd over 3 callsites
  • → leverage: ChangeDetector gjenbrukbar fra web-laget uten å røre DB
  • → interface krymper fra 310 linjer til 3 smale seams
  • → ChangeDetector testbar med plain dicts — ingen MariaDB nødvendig

6. Konsolider scoring-implementasjonen

Speculative in-process

  • → testbar med plain dicts — ingen DB eller HTTP
  • → spekulativ: lav hast inntil reglene divergerer videre

Top recommendation

Start med kandidat 1 — deepen database write module

update_database() er den høyeste-friksjon-modulen i kodebasen: 310 linjer, 7 ansvar, ingen locality. Å trekke ut ChangeDetector alene låser opp tester som ikke trenger database, gjør prisendring-logikken gjenbrukbar i web-laget, og gir resten av refaktoreringen en ren intern seam å ankre til.
